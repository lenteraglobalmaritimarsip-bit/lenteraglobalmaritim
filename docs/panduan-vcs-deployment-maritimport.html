Panduan VCS dan Deployment

MaritimPort Shipping Agency Work Portal

Tujuan: pengembangan aplikasi dapat berjalan tanpa mengubah aplikasi online yang sedang operasional.

1. Struktur Branch

BranchFungsiDeployment
mainVersi stabil yang sudah disetujuiProduction/online
developGabungan fitur untuk pengujianStaging, bila tersedia
feature/*Satu fitur atau perbaikan tertentuTidak langsung online

2. Alur Pengembangan

feature/nama-fitur
        |
        v
     develop  -- test/typecheck/build --> staging
        |
        v
      main   -- approval/release ------> production

Jangan mengembangkan fitur langsung di main. Branch production hanya menerima perubahan yang sudah diuji.

3. Perintah Git

git checkout main
git pull origin main
git checkout -b develop
git push -u origin develop

# Membuat fitur baru
git checkout develop
git pull origin develop
git checkout -b feature/nama-fitur

# Menyimpan pekerjaan
git add .
git commit -m "feat: deskripsi perubahan"
git push -u origin feature/nama-fitur

Setelah pengujian selesai, lakukan Pull Request dari feature/* ke develop. Setelah staging disetujui, Pull Request dari develop ke main.

4. Pisahkan Environment

Production dan development sebaiknya menggunakan project Supabase yang berbeda.

EnvironmentDatabaseBranch
DevelopmentSupabase development/stagingfeature/*, develop
ProductionSupabase productionmain
# .env.development
VITE_SUPABASE_URL=https://staging-project.supabase.co
VITE_SUPABASE_ANON_KEY=staging-key

# .env.production
VITE_SUPABASE_URL=https://production-project.supabase.co
VITE_SUPABASE_ANON_KEY=production-key

Jangan commit file environment yang berisi credential. Simpan credential pada Environment Variables di layanan deployment.

5. Perubahan Database

  1. Uji perubahan schema di Supabase staging.
  2. Backup database production.
  3. Jalankan migration di production pada waktu yang disetujui.
  4. Verifikasi tabel, kolom, index, dan data.
  5. Deploy aplikasi setelah schema siap.

Gunakan database/schema.sql sebagai sumber schema utama project. Jangan mengubah schema production secara manual tanpa mencatat perubahannya di Git.

6. Checklist Sebelum Production

  • npm run lint berhasil.
  • npm run build berhasil.
  • Login Admin dan role utama diuji.
  • Fix Tariff dan Expenses Item diuji.
  • Alur EPDA otomatis dan manual diuji.
  • Alur FDA otomatis dan manual diuji.
  • Supabase production sudah memiliki schema terbaru.
  • Backup database tersedia.
  • Perubahan sudah melalui Pull Request.

7. Rollback

Jika release bermasalah, kembalikan deployment ke commit stabil sebelumnya. Jangan langsung menghapus data database. Untuk perubahan schema, siapkan migration rollback atau perubahan kompatibel sebelum release.

git log --oneline -10
git checkout main
git revert <commit-yang-bermasalah>
git push origin main
